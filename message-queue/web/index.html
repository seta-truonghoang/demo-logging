🔑 Key-Based Partitioning vs Round-Robin

In Kafka, the way a message is routed to a partition is highly critical for application scalability and correctness.

  • Hash-Key Partitioning: Kafka hashes the Message Key and maps it to a specific partition. Messages with the same key always land in the same partition, ensuring strict ordering of event delivery for a specific entity.
  • Round-Robin: If no key is provided, Kafka distributes messages evenly across partitions. This achieves excellent load balancing but sacrifices ordering.

⚖️ Consumer Groups & Live Rebalancing

A Consumer Group is a group of consumers sharing the same Group ID that cooperatively process messages from a topic.

  • Kafka automatically divides the topic's partitions among the group's active workers. Each partition is assigned to exactly one consumer in the group.
  • Live Rebalancing: Try toggling workers on/off! When a consumer joins or leaves, Kafka triggers a rebalance protocol, reshuffling partition assignments across the remaining active consumers so that no message is missed.
